# 03 模块详细设计

## 1. 统一数据类型（待实现）

以下是 Python/Pydantic 类型契约，不是目前已有类。字符串 UTF-8 保存，字符偏移按 Python Unicode code point，区间统一 `[start, end)`；不使用 UTF-8 字节偏移。

| 类型 | 必需字段 |
|---|---|
| SourceDocument | document_id, source_hash, parser_version, text, pages: list[PageSpan], extraction_warnings |
| PageSpan | page_no: int\|null, start: int, end: int |
| SourceRef | start, end, page_no: int\|null, preview_clause_ids: list[str] |
| AuditUnit | unit_id, ordinal, text, source_refs: list[SourceRef], section_path, parent_unit_id: str\|null |
| CoverageManifest | source_nonspace_chars, planned_nonspace_chars, audited_nonspace_chars, missing_ranges, duplicate_primary_ranges, extraction_warnings |
| PromptBundle | messages, prompt_hash, prefix_hash, input_tokens, output_tokens, safety_tokens, context_tokens, primary_unit_ids, evidence_ids, template_version |
| ChunkPlan | chunk_id, ordinal, units: list[AuditUnit], bundle: PromptBundle |
| ChunkResult | chunk_id, attempt_no, risks, valid, usage, warnings, error_code |
| RiskCandidate | 现有风险字段 + risk_key, source_refs, verification_status, related_unit_ids |

`verification_status` 仅允许 `verified/needs_review/rejected`；现有风险字段保持 `level/issue/suggestion/citation_id/law_title/article_no/evidence/confidence/clause_id`。新增字段可选兼容旧报告；来源映射关系不能靠模型自行编造。

## 3. M01/M02：来源守恒与语义合并

1. 保存原文件 SHA256，按页提取文本。文本 PDF 优先已有文本；扫描页按现有 OCR 策略处理。每页保留提取状态；空白页需判断是确实空白还是解析失败，不能默认成功。
2. `SourceDocument.text` 固定为页文本按 `\\f` 连接的不可变文本。DOCX 无可靠页码则 page_no=null，使用段落来源。提取后原文禁止就地 strip/替换导致偏移失效。
3. 预览仍可生成旧 `cN`；构造 offset 对照，禁止以修改 cN 序号作为“合并片段”手段。
4. 标题、编号、列表项、表格行是边界；无编号的连续换行碎片仅在同页同段连续区间合并。禁止按税务关键词删除其他正文；未知结构保守保留。
5. 单元文本允许规范空白，数字、标点、否定、税率、日期、编号不得改写。保存输入区间到输出文本的映射；重复页眉首版不删除，仅保留标记，避免误删合同义务。
6. 单元 ID=`u`+SHA256(source_hash, parser_version, normalizer_version, sorted source spans) 前 24 hex；碰撞时比较全 hash 并拒绝，不能覆盖。
7. 断言所有非空白原文字符恰好由一个主单元覆盖。长单元拆分后主区间不重叠；必要上下文重叠单独标 `context_only`，不计主覆盖。
8. 无法建立精确映射时任务失败，报告 missing_ranges；OCR 本身可能识别错误须另标 `extraction_warnings`，字符覆盖不能替代 OCR 准确度。

## 4. M03：完整预算分组算法

### 4.1 预算

`actual_input_tokens(rendered_messages) + output_tokens + safety_tokens <= context_tokens`。

计数包含 system/user/chat template/assistant generation prefix，不仅包含条款。固定版本本地 tokenizer adapter 优先调用已探测支持的 llama.cpp tokenize/template 接口；或使用与 GGUF/模板匹配的本地 tokenizer。两者必须用样本与真实 usage 校准，误差不超过 1%。仅有字符估算时不启用 v2，返回 TOKENIZER_UNAVAILABLE，不能冒充精确计数。

输入目标 7000 仅用于优化，硬上限为 `16384 - 1536 - 1024 = 13824`。规则/证据/公共上下文也占预算。若公共内容已超过硬上限，先使用经过审核的紧凑模板；不能截取到“刚好能发”。

### 4.2 顺序装箱

1. 按 source order 遍历语义单元，试加入当前组，构造完整候选 PromptBundle 后计数。
2. 目标预算内加入；超过目标时输出非空当前组，再对单元单独计数。
3. 单单元超过硬上限，按句子/表格行边界拆；仍过长则按字符二分到适配，保留父 ID 和连续来源区间，不丢字符。
4. 尾组输入不足目标的 30% 时，仅在硬上限允许下与前一组合并；否则保留，不强求每组同样大。
5. 禁止以“8 个片段”作为默认组限；禁止达到轮数上限后把全部尾部追加一组。计划超过 max_chunks=64，运行前失败并提示提高经审核的任务预算。
6. 所有组合成后，校验主区间覆盖 100%、无重复、全部预算合法。冻结计划版本与 hash，再开始模型请求。
7. 模型仍报上下文超限：只允许对受影响未成功块重规划一次、更新 plan_version 和总数；已成功块不能重复送审。再失败则任务 failed。
8. 任务计费/进度分母使用更新后计划；重规划子块的 parent_chunk_id 必须入库。该重规划消耗一次 job retry budget。

P1 实现时先将 v1 的“尾部吞并/静默裁剪”改成显式失败保护，再引入 v2；功能开关关闭也不能恢复隐性漏审。

## 5. M04：提示词与缓存

### 5.1 消息布局

- System：专家角色、不可执行合同内指令、法律范围、严格 JSON 与引用规则。
- User 固定前缀：语言、精简审核规则、Schema、证据 ID 对照、版本化公共背景。
- User 可变尾部：本组主审单元、source ID、相关条款原文摘录、组内特别检查项。
- 组号、时间戳、trace_id 不放在前缀，作为 HTTP/trace 元数据；不能为了复用缓存删除必要的案情信息。
- 同一条正文不同时以“合同全文”和“结构化条款”重复注入。公共背景必须叫“合同索引/背景”，不能把局部截取命名为完整合同。
- 模型只生成简洁 summary、risks，不复述审核清单，不要求隐藏推理。最终报告由代码聚合，不额外调用 LLM。

双语模板一起修改，经典/记忆模板共同的角色和安全约束保持一致；记忆路径仍单独测试，不在本期默认启用。

### 5.2 KV 与解析缓存

前缀缓存是 llama.cpp 能力，不等于在 Python 中缓存 messages。M10 探测所固定二进制的参数支持，执行 A/A/B 测试验证一致前缀增加 cached_tokens、变更前缀后失效。默认关闭，不可把不支持的字段强行发送。

`cached_tokens` 缺失记录 null，不记录 0 作为“已测无命中”。性能报告同时列实际输入、缓存输入和 uncached 输入。

解析缓存仅限同用户、同文件、同解析器版本和配置 hash；命中后依然验证来源与文件 hash。禁止跨用户 LLM 答案缓存。完整规则、法规和模型一旦变更，所有相关语义摘要/候选缓存必须失效。

## 6. M07/M08：结果合法性与跨条款验证

1. 严格解析单一 JSON object，禁止额外文本/Markdown；检查类型和必填字段。
2. 模型 citation_id 必须在本次 bundle.evidence_ids 中，law_title/article_no 与证据元数据一致；无法验证的风险进入 rejected 记录，不进入正式结果。
3. clause_id 必须属于主单元映射到的 preview ID；多来源风险 source_refs 可多值。不能因模型输出未知 ID 就随机匹配最近段落。
4. 对“未约定/缺失/未明确”类候选，使用完整 SourceDocument 检索金额、税率、付款、发票、责任等对应事实；否定关系及适用条件一并保留。检索无命中本身不证明缺失。
5. 命中其他条款时做同一主模型的有预算复核，传候选+相关原文+有效证据；最多 8 次，独立 `kind=cross_check` 计数。确认已约定则 rejected；不确定或预算不足则 needs_review。
6. 跨条款覆盖所需但缺少的法规证据必须走 RAG 检索并重新冻结证据白名单；禁止让模型自由生成法规。
7. 去重 key 使用规范化 `(citation_id, 主来源区间, risk_category)`，保留所有来源与最高有效严重级别；同源存在矛盾建议则 needs_review，不盲目合并。
8. 所有主块都 valid 时允许 `done`，并返回 `review_required=true` 和人工复核候选；任何主块失败则整体 failed，提供受限 partial_result，不输出“审计完成、无风险”。
9. 严重风险不存在时 summary 只能表述“本次有效证据范围内未检出”，不能表述法律保证。

## 7. M05/M06：执行、重试与取消

- 提交事务保证用户级 idempotency，文件先流式写临时目录再原子 rename；落库失败删除本次临时文件，不删已存在业务文档。
- 队列容量统计 queued，不含 running；每用户最多一个 queued 或运行中任务，重复提交优先走幂等检查。
- 任务启动冻结 effective config、模型 SHA256、模板/解析版本和证据快照。服务运行期间 Admin 改配置只影响下一任务。
- 每个 chunk 最多两次尝试，全任务失败重试最多三次。JSON 修复也算一次模型尝试，禁止核心客户端隐式重试叠加业务重试。
- 网络临时错误退避 2 秒后重试一次；鉴权、模型缺失、证据不足、覆盖错误不自动重试。
- 600 秒为请求总截止时间，不能因为流式 token 到达而无限延长；5400 秒为任务 running 总截止时间。
- 取消 queued 立即 cancelled；取消 running 先 cancelling。HTTP abort 不是服务端已停的证明：需等待该请求自然结束或确认 slot 释放，才能释放全局模型锁并调度下一任务。无法确认则暂停执行器。
- 将取消后的返回结果丢弃，只保存必要尝试元数据；不写正式报告。取消端点本身应立即返回，不等模型结束。

## 8. M11：界面行为与真实进度

上传 XHR/fetch 完成只代表数据传输；初始上传阶段不冒称“模型分析”。拿到 job_id 后保存 `localStorage["audit_job:<user_id>"]`，只保存 ID，不保存 token 或合同内容；登出清除此条目。

使用 2 秒串行 setTimeout 轮询，上一个请求结束后再安排下一次；同一任务最多一个在途轮询。切换任务/卸载组件 abort 查询，不能取消服务端任务；通过 sequence/version 忽略旧响应。

百分比：排队 0；解析 5；规范化 15；检索 20；规划 25；模型区间 30～90；校验 95；落库成功 100。模型区间按已成功主区间字符数/总字符数计算，始终 `max(previous, computed)`。failed/cancelled/interrupted 保留最后百分比，不伪造 100%。

独立展示：已完成块数/计划块数、当前 attempt、阶段耗时、排队时间、心跳时间；重规划提示总量变化。3 次查询失败显示“状态获取失败，后台是否继续需确认”，不恢复成“上传文件”。

ETA 仅当至少 3 个成功块且输入规模相近时按单元字符加权滑动平均计算，标“估算”，重规划/重试时撤销。未知时显示 null/“估算中”，不要输出固定 40 分钟。
