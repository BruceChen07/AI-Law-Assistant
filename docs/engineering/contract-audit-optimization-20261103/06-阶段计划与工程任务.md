# 06 阶段计划与工程任务

## 1. 时间顺序与资源假设

排期从审核批准后的 T0 起算，不以文档日期作为自动开工日。按1名主工程师、兼职法务/财税验收人、兼职运维估计 **20个工程人日、27个工作日窗口**；其中真实模型基准占用专用机器约80～120小时，P5预留10个工作日、工程师投入3人日，其余为自动化运行/等待。LLM可加速编码，不代替人工标注和长时间基准测试。无法获得真实脱敏样本/维护窗口时，日历排期顺延，不伪造验收。

| 阶段 | 相对时间/人日 | 前置 | 主要交付 | 阶段门 |
|---|---|---|---|---|
| P0 基线与隔离 | D1～D2 / 2 | 设计审核、仓库读写权限 | 环境/代码清单、问题基线、隔离配置、测试样本 | G0：无生产写入、复现旧问题 |
| P1 全文覆盖保护 | D3～D6 / 4 | G0 | 来源映射、均衡计划、失败保护、覆盖测试 | G1：预算与覆盖不变量通过 |
| P2 提示词与执行优化 | D7～D9 / 3 | G1 | 双语紧凑模板、能力探测、参数统一、验证器 | G2：合法引用和质量初测通过 |
| P3 持久化任务 | D10～D13 / 4 | G2 | 迁移、仓储、执行器、API、旧入口适配 | G3：队列/取消/重启/隔离通过 |

## 4. 状态记录规则

每任务状态枚举 TODO/IN_PROGRESS/BLOCKED/DONE/WAIVED。本次所有实现任务初始为 TODO。DONE 必须有证据链接，不能仅凭代码已写。WAIVED 必须有审批人、日期、原因和到期时间；R01/R02/R03 安全不变量不能豁免。

BLOCKED 必须写出具体依赖和可继续做的其他任务；禁止用“待优化”“有问题”等模糊状态。跨阶段跳转必须更新 dependencies 和 gate，不得只更新百分比。

## 5. 阶段回退

- G1失败：回到T10/T11，不进入参数调优。
- G2失败：保留原始模板和全覆盖计划对照，修合法性/提示词，不改验收阈值。
- G3失败：保留线程池兼容入口，但禁止生产开启新任务API。
- G4失败：旧页面继续兼容，API开发可保留关闭开关。
- G5性能失败：保留正确性修复，提交未达标报告；不以减小覆盖范围解决。
- G6失败：恢复已验证的保护版本及数据库备份策略，停止接新单，保留失败证据。
