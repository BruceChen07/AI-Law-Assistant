# 05 数据库与数据生命周期

## 1. 复用与迁移原则

既有主库为配置 `db_path` 指向的 SQLite；当前为 `data/app.db`。保留 `users/documents/contract_audit/article/article_embedding` 等表，不把新任务混入税审的 `audit_runtime_session`。LLM 完整 trace 现有独立库/JSONL继续由适配器关联。

新增六张业务表和一张迁移版本表，全部前缀 `contract_audit_`。下列 DDL 是**设计文本**；实现者生成 `app/migrations/001_contract_audit_jobs.sql` 并在测试副本验证。本次不创建/更新数据库。

SQLite 每连接启用 foreign_keys，busy_timeout=1000；本地数据库启用 WAL、synchronous=FULL。现有历史外键可能不完整，迁移前执行 foreign_key_check：发现问题必须报告并处理，不自动删孤儿记录。SQL CHECK 校验状态和数值，JSON 结构由 Pydantic 校验，避免依赖不可用的 JSON 扩展。

## 2. DDL 契约

```sql
CREATE TABLE IF NOT EXISTS contract_audit_schema_version (
  version INTEGER PRIMARY KEY,
  checksum TEXT NOT NULL,
  applied_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS contract_audit_job (
  job_id TEXT PRIMARY KEY,
  audit_id TEXT NOT NULL UNIQUE,
  owner_id TEXT NOT NULL REFERENCES users(id),
  document_id TEXT NOT NULL REFERENCES documents(id),
  idempotency_key TEXT NOT NULL,
  request_fingerprint TEXT NOT NULL,
  retry_of TEXT REFERENCES contract_audit_job(job_id),
  status TEXT NOT NULL CHECK(status IN
    ('queued','running','cancelling','done','failed','cancelled','interrupted')),
  stage TEXT NOT NULL,
  last_active_stage TEXT,
  progress INTEGER NOT NULL DEFAULT 0 CHECK(progress BETWEEN 0 AND 100),
  version INTEGER NOT NULL DEFAULT 1,
  plan_version INTEGER NOT NULL DEFAULT 0,
  cancel_requested INTEGER NOT NULL DEFAULT 0 CHECK(cancel_requested IN (0,1)),
  review_required INTEGER NOT NULL DEFAULT 0 CHECK(review_required IN (0,1)),
  created_at TEXT NOT NULL,
  started_at TEXT,
  updated_at TEXT NOT NULL,
  heartbeat_at TEXT,
  finished_at TEXT,
  executor_id TEXT,
  source_hash TEXT NOT NULL,
  parser_version TEXT,
  normalizer_version TEXT,
  prompt_version TEXT NOT NULL,
  model_hash TEXT NOT NULL,
  policy_hash TEXT NOT NULL,
  options_json TEXT NOT NULL,
  config_snapshot_json TEXT NOT NULL,
  evidence_snapshot_json TEXT,
  source_manifest_json TEXT,
  coverage_json TEXT,
  metrics_json TEXT NOT NULL DEFAULT '{}',
  error_code TEXT,
  error_message TEXT,
  UNIQUE(owner_id, idempotency_key)
);
CREATE INDEX IF NOT EXISTS idx_ca_job_queue
  ON contract_audit_job(status, created_at, job_id);
CREATE INDEX IF NOT EXISTS idx_ca_job_owner
  ON contract_audit_job(owner_id, created_at, job_id);
CREATE INDEX IF NOT EXISTS idx_ca_job_document
  ON contract_audit_job(document_id, created_at);

CREATE TABLE IF NOT EXISTS contract_audit_unit (
  job_id TEXT NOT NULL REFERENCES contract_audit_job(job_id),
  unit_id TEXT NOT NULL,
  ordinal INTEGER NOT NULL,
  parent_unit_id TEXT,
  unit_text TEXT NOT NULL,
  section_path TEXT NOT NULL DEFAULT '',
  source_refs_json TEXT NOT NULL,
  content_hash TEXT NOT NULL,
  PRIMARY KEY(job_id, unit_id),
  UNIQUE(job_id, ordinal)
);

CREATE TABLE IF NOT EXISTS contract_audit_chunk (
  job_id TEXT NOT NULL REFERENCES contract_audit_job(job_id),
  chunk_id TEXT NOT NULL,
  ordinal INTEGER NOT NULL,
  plan_version INTEGER NOT NULL,
  parent_chunk_id TEXT,
  kind TEXT NOT NULL CHECK(kind IN ('chunk','cross_check')),
  status TEXT NOT NULL CHECK(status IN
    ('planned','running','done','failed','cancelled','superseded')),
  unit_ids_json TEXT NOT NULL,
  input_tokens INTEGER NOT NULL CHECK(input_tokens >= 0),
  output_limit INTEGER NOT NULL CHECK(output_limit > 0),
  context_limit INTEGER NOT NULL CHECK(context_limit > 0),
  safety_tokens INTEGER NOT NULL CHECK(safety_tokens >= 0),
  prompt_hash TEXT NOT NULL,
  prefix_hash TEXT NOT NULL,
  completed_at TEXT,
  result_json TEXT,
  PRIMARY KEY(job_id, chunk_id),
  UNIQUE(job_id, plan_version, ordinal),
  CHECK(input_tokens + output_limit + safety_tokens <= context_limit)
);

CREATE TABLE IF NOT EXISTS contract_audit_attempt (
  attempt_id TEXT PRIMARY KEY,
  job_id TEXT NOT NULL,
  chunk_id TEXT NOT NULL,
  attempt_no INTEGER NOT NULL CHECK(attempt_no BETWEEN 1 AND 2),
  trace_id TEXT NOT NULL,
  status TEXT NOT NULL CHECK(status IN
    ('running','success','failed','discarded','interrupted')),
  started_at TEXT NOT NULL,
  finished_at TEXT,
  queue_wait_ms INTEGER,
  duration_ms INTEGER,
  ttft_ms INTEGER,
  prefill_ms INTEGER,
  decode_ms INTEGER,
  input_tokens INTEGER,
  cached_tokens INTEGER,
  output_tokens INTEGER,
  effective_params_json TEXT NOT NULL,
  response_hash TEXT,
  finish_reason TEXT,
  error_code TEXT,
  error_message TEXT,
  raw_trace_path TEXT,
  UNIQUE(job_id, chunk_id, attempt_no),
  FOREIGN KEY(job_id, chunk_id)
    REFERENCES contract_audit_chunk(job_id, chunk_id)
);
CREATE INDEX IF NOT EXISTS idx_ca_attempt_job
  ON contract_audit_attempt(job_id, started_at);

CREATE TABLE IF NOT EXISTS contract_audit_event (
  job_id TEXT NOT NULL REFERENCES contract_audit_job(job_id),
  seq INTEGER NOT NULL,
  ts TEXT NOT NULL,
  event_type TEXT NOT NULL,
  version INTEGER NOT NULL,
  status TEXT NOT NULL,
  stage TEXT NOT NULL,
  detail_json TEXT NOT NULL,
  PRIMARY KEY(job_id, seq)
);

CREATE TABLE IF NOT EXISTS contract_audit_parse_cache (
  owner_id TEXT NOT NULL REFERENCES users(id),
  cache_key TEXT NOT NULL,
  source_hash TEXT NOT NULL,
  parser_version TEXT NOT NULL,
  parse_config_hash TEXT NOT NULL,
  artifact_path TEXT NOT NULL,
  artifact_hash TEXT NOT NULL,
  artifact_bytes INTEGER NOT NULL CHECK(artifact_bytes >= 0),
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  last_access_at TEXT NOT NULL,

CREATE INDEX IF NOT EXISTS idx_ca_cache_expiry
  ON contract_audit_parse_cache(expires_at);
```

`unit.ordinal` 为存储顺序，拆分时新增子单元并重编序；历史已执行 plan 的 unit ID 不改变。`chunk.ordinal` 在同 plan_version 内含主块和附加复核唯一排序。superseded 块不再执行，不计入最终覆盖；旧尝试仍保留追溯。每个计划主块引用的 unit ID 必须属于同 job，由仓储事务验证 JSON 关联。

## 3. JSON 列定义

| 列 | 结构/约束 |
|---|---|
| options_json | 04 的规范化业务字段，不含临时路径和凭据 |
| config_snapshot_json | engine/policy/effective LLM params、runtime/template hash、语言、版本；密钥仅 credential_ref，禁止存值 |
| evidence_snapshot_json | `[{citation_id,law_title,article_no,content,content_hash,source_version}]`；按 citation_id 稳定排序 |
| source_manifest_json | `{artifact_path,artifact_hash,text_length,pages,extraction_warnings,nonspace_chars}`；path相对 data_dir |
| coverage_json | 03 CoverageManifest + plan_version；空计划为 null，不假设100% |
| metrics_json | `{queue_wait_ms,elapsed_ms,stage_durations_ms,request_started,request_completed,retries_used,cross_checks_used,input_tokens,cached_tokens,output_tokens,eta_ms}`；时长缺失 null |
| source_refs_json | 03 SourceRef 数组；区间合法、递增、正文映射校验 |
| unit_ids_json | 有序字符串数组；cross_check 可含多个相关单元，但不能增加主覆盖 |
| result_json | 经 M07 校验的 ChunkResult；done 时必须非空；无风险允许 risks=[] |
| effective_params_json | 此尝试最终 model/temperature/max_tokens/timeout/thinking/cache 和 context 配置 |
| detail_json | 仅元数据；不得放用户 token、原文、完整模型响应 |

现有 `contract_audit.result_json` 继续存 `result` 业务对象；新增版本/覆盖摘要纳入 result 的 metadata，API meta 由 job 再组装。旧 report 读取逻辑不依赖新表即能处理历史结果。

## 4. 事务与一致性

1. **提交**：临时文件流式写入、hash、rename；单短事务登记 documents/upload_log、job 和首事件。现有 insert_document 按文件名去重不适合此处，新增以 owner+source_hash 校验的显式仓储方法，禁止跨用户按文件名误复用。
2. **认领**：BEGIN IMMEDIATE；取 FIFO queued；UPDATE ... WHERE status='queued'；affected_rows=1 才执行。事务内不解析文件、不发网络请求。
3. **进度**：读 version，写状态和 version+1，同事务生成 seq=max(seq)+1 事件；心跳只更新 heartbeat/version。事件 seq 在 job 内递增。
4. **完成尝试**：attempt 完成、chunk 合法结果、coverage、metrics、job version 与事件同事务更新。
5. **完成任务**：校验 coverage=1；INSERT 既有 contract_audit（id=audit_id，status=done）、UPDATE job done 与完成事件一起 commit。事务失败仍非 done。
6. **失败/取消**：保存当前覆盖和错误，主结果不写成功行；遗留 partial 保留在 chunk。兼容失败记录可写 contract_audit status=failed，但不得覆盖已成功结果。
7. **锁重试**：最多3次，间隔100/300/600ms，总等待含 busy timeout 必须≤2秒，调用设置剩余截止时间；耗尽抛 PERSISTENCE_FAILED。指标写入失败不可以吞掉。
8. **断电**：SQLite 恢复后识别未结束 attempts 为 interrupted，重启不直接把它们视为成功。报错内容只存清洗后的摘要。

## 5. 文件与缓存生命周期

- 所有路径以 data_dir 为边界，resolve 后校验 containment 和 symlink，禁止请求指定任意绝对路径。
- 源文件保留现有业务策略，删除必须用户/管理员授权，不能由缓存清理器处理。
- 新 artifact 建议 `data/audit-artifacts/<job_id>/source.json`，保存提取文本与映射；敏感级别同合同。文件临时写+fsync+rename，入库前计算 hash；坏文件不能返回缓存命中。
- 解析 cache_key=SHA256(owner_id, source_hash, parser_version, OCR engine/version/languages/dpi, normalization-input-version)。
- 解析缓存 TTL 7天，总上限2 GiB，LRU；在用的 artifact 不删除。job 的 canonical artifact 独立于 cache 副本，过期 cache 不得破坏 job 回放。
- KV cache 由 llama.cpp 生命周期管理，不在 SQLite 储存；只复用同用户同任务 slot 前缀，切用户/任务时清理slot或明确隔离。
- 原始 LLM Trace 默认关闭。诊断模式使用受限目录，7天过期且总上限1 GiB；元数据事件/attempts保留90天。业务报告及其最小来源映射不自动删。
- 90天清理只处理终态任务的诊断事件、尝试详情，保留任务摘要与报告链；执行前导出清理清单，生产由管理员批准。
- 小模型实验即使启用，也必须记录实际模型 hash，不能仅记录 auto。

## 6. 迁移与回滚

迁移器先校验当前版本与 DDL checksum，`PRAGMA integrity_check`、foreign_key_check；然后在事务中建表/索引并写版本。重复执行必须无数据变化，同版本不同 checksum 必须拒绝。

生产发布前停止接单并排空；使用 SQLite backup API 或停止服务后的完整备份，不在线直接复制 app.db 而漏 WAL。备份需要文件 hash、时间戳、schema_version、行数与恢复测试结果。

回滚优先关闭新路由入口并恢复上一**已包含覆盖保护**的代码版本，新增表保留，不自动 DROP。若需恢复数据库，必须确认发布后新增结果已导出并批准数据恢复点，避免回滚丢业务记录。旧的不安全漏段算法不作为可接受回滚目标。
