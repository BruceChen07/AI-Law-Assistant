# 04 接口与错误契约

## 1. 通用规则

本章新端点均待实现。现有 API 不统一增加 `/api` 前缀；合同接口继续位于 `/contracts/...`。鉴权沿用 `Authorization: Bearer <token>`，但必须补充 inactive 用户拒绝和资源所有权检查。普通用户只能访问自己的任务、文件与结果；管理员通过明确管理权限访问，记录访问审计。其他用户资源一律返回 404，避免泄露存在性。

新接口仅返回 JSON UTF-8。时间为 UTC `YYYY-MM-DDTHH:mm:ss.sssZ`，持续时间用整数毫秒，未知数值为 null，不用 0 代替未知。请求 ID 为服务端 UUID；客户端传 `X-Request-ID` 仅作为关联值校验后保存。禁止响应中暴露文件绝对路径、密钥、完整 prompt 或内部堆栈。

## 2. 端点定义

| 方法/路径 | 输入 | 成功返回 | 失败/权限 |
|---|---|---|---|
| POST `/contracts/audit-jobs` | multipart，见 2.1 | 首次 202 + JobView；相同幂等请求 200 | 401/404/409/413/415/422/429/503/507 |
| GET `/contracts/audit-jobs` | status 可选；limit 默认20，1～100；offset 默认0 | 200 `{items: JobView[],total:int}` | 按 owner 过滤后分页；created_at DESC, job_id DESC |
| GET `/contracts/audit-jobs/{job_id}` | UUID | 200 JobView | 401/404 |
| GET `/contracts/audit-jobs/{job_id}/result` | UUID | done: 200 ResultView | 非 done: 409 JOB_NOT_DONE |
| GET `/contracts/audit-jobs/{job_id}/partial-result` | UUID | failed/interrupted: 200 PartialResultView | 其他状态 409；只允许查看已合法完成块 |
| POST `/contracts/audit-jobs/{job_id}/cancel` | 空对象 | queued:200；running:202；cancelling/已终态:200，均返回 JobView | 终态不变；401/404 |
| POST `/contracts/audit-jobs/{job_id}/retry` | 空对象 + Idempotency-Key | 202 新 JobView 或幂等 200 | 仅 failed/interrupted/cancelled；源文件不存在404；其他409 |
| GET `/contracts/audit-jobs/{job_id}/events` | after_seq 默认0；limit默认100，最大500 | 200 `{events:EventView[],next_seq:int}` | 事件不含合同正文 |

静态集合路由必须在可能冲突的 `/{document_id}` 路由前注册。当前 `/contracts/{document_id}/preview`、报告导出等保持路径不变。

### 2.1 提交字段

`Idempotency-Key` 必填，8～128 个 ASCII 字符 `[A-Za-z0-9._:-]`；以 `(owner_id, key)` 唯一。原始 HTTP 无 Content-Length 也要流式计数，超过 50*1024*1024 字节立即停止。校验扩展名、文件签名和解析类型；DOCX 解压后累计 ≤200 MiB、条目 ≤10000，拒绝 zip path traversal。

表单 `file` 与 `document_id` 必须恰好提供一个。后者复用当前用户拥有的 active document，只读源文件，不从请求接收服务器路径。输入文件不可修改。

| 字段 | 类型/默认 | 校验 |
|---|---|---|
| title | string / 原文件无扩展名 | 最长200 |
| language | `"zh"` | zh/en |
| audit_mode | `"rag"` | rag/baseline，保留原业务语义 |
| risk_detection_mode | `"balanced"` | 本版新 API 只支持 balanced；其他422，不静默降级 |
| region / industry | `""` | 每项最长100 |
| date | null | `YYYY-MM-DD` 合法日期 |
| tax_focus | true | multipart `"true"/"false"`，不得依赖字符串 truthiness |

新 API 不暴露旧调试型分块/模型参数；旧端点仍解析旧字段，但 v2 以安全预算为最终约束。baseline 模式没有有效白名单证据时，输出“证据不足、需人工补充”，不捏造法规或绕过引用规则。

幂等 fingerprint=SHA256(owner_id + source_hash + canonical_business_options)。首次同时冻结实际配置；相同 key/fingerprint 即使随后默认配置变化也返回原任务。相同 key 不同 fingerprint 返回409 IDEMPOTENCY_CONFLICT。retry fingerprint 包含原 job_id；同 key 不能用于上传与 retry 两种操作。

```json
  "status": "running",
  "stage": "auditing",
  "last_active_stage": "auditing",
  "progress": 55,
  "message_code": "AUDITING_CHUNKS",
  "created_at": "2026-11-03T06:00:00.000Z",
  "started_at": "2026-11-03T06:00:01.000Z",
  "updated_at": "2026-11-03T06:08:00.000Z",
  "heartbeat_at": "2026-11-03T06:08:00.000Z",
  "finished_at": null,
  "elapsed_ms": 479000,
  "queue_wait_ms": 1000,
  "eta_ms": null,
  "version": 19,
  "plan_version": 1,
  "review_required": false,
  "detail": {
    "execution_path": "classic_v2",
    "llm_request_current_index": 4,
    "llm_request_total_planned": 7,
    "llm_request_total_upper_bound": 18,
    "llm_request_exact_total_known": false,
    "llm_request_completed": 3,
    "llm_request_current_label": "chunk-004",
    "llm_request_kind": "chunk",
    "llm_request_status": "running",
    "llm_request_retry_index": 0,
    "chunks_completed": 3,
    "chunks_total": 7,
    "coverage_planned": 1.0,

    "output_tokens": 1600

  "error": null

```

job_id UUID；audit_id 新接口等于 job_id，旧接口可保留客户端 audit_id。进度0～100整数。比例0～1。`version` 每次持久化状态变更/心跳递增，UI 只应用更大版本。

请求计数包含所有主块、失败重试和跨条款复核，completed 包括已返回的成功/失败尝试；chunks_completed 只统计成功主块，不能用请求数计算覆盖率。planned 为当前已知调用数，upper_bound=主计划调用数+剩余全局重试预算+剩余 cross_check 预算；重规划时同步调整，不得小于 planned。全部计划确定前 exact_total_known=false。

`input_tokens/output_tokens` 是已返回调用 usage 总和，尚无 usage 时为0；cached_tokens 任一已返回调用缺失时总值 null，并在事件中保留已知部分。heartbeat 表示执行器存活，不代表模型 token 仍增加。

`error` 为 null 或 `{code,message,retryable,request_id}`；message 本地化、安全且可操作。

### 2.3 结果与事件

ResultView 保留 `{audit_id,document_id,result,meta,risk_summary}`。`result` 继续包含原 risks/summary/citations/final_report 等。`meta` 新增：

- engine_version、prompt_version、model_hash、policy_hash、plan_version；
- source_hash、coverage_planned、coverage_audited、review_required；
- warnings: list[{code,message}]，execution_path，total_elapsed_ms；
- rejected_risk_count、needs_review_count；完整 rejected 内容只给授权诊断。

PartialResultView=`{complete:false,job_id,valid_results:[ChunkResult],missing_ranges,error}`。不得通过标准“完整审计报告”导出接口导出；后续如支持 partial 导出，必须有显著未完成水印且另行设计。

EventView=`{seq:int,job_id,event_type,ts,status,stage,version,detail:object}`。event_type 为 state_changed/chunk_started/chunk_finished/retry_scheduled/plan_changed/quality_warning；心跳只更新任务表，不每5秒追加事件。

## 3. 旧接口适配

| 现有入口 | v2 开启后行为 |
|---|---|
| POST `/contracts/audit` | 通过同一 job service 提交，异步等待终态，完成仍返回原200结构；不能再直接调用重计算 |
| POST `/contracts/{document_id}/pipeline/run` | 同一队列，转 async await 等待，不用阻塞线程等待占满 threadpool |
| GET `/contracts/audit/{audit_id}/progress` | 查询新任务表；旧字典任务仅在登记 owner 后可兼容；不允许仅“已登录即可查任意 ID” |
| 现有报告/预览 | 完整 done 结果写既有 contract_audit，来源定位仍支持 cN |

旧 audit_id 校验为1～64个 `[A-Za-z0-9_-]`（UUID连字符合法）。同 audit_id 不得覆盖已有任务；相同 owner/fingerprint 返回原状态，冲突409；其他用户同 ID 返回404。无 audit_id 时服务端生成 UUID。

旧客户端断开连接不取消任务；HTTP 超时不自动重发 POST。401 只影响查询，任务仍归原用户；重新登录后由任务列表恢复。新前端以短提交为默认，未知是否提交成功时使用同幂等 key 重试。

## 4. 异常矩阵

| code | 提交 HTTP / 运行终态 | 自动处理 | 用户/运维动作 |
|---|---|---|---|
| AUTH_REQUIRED / ACCOUNT_DISABLED | 401/403 | 不重试 | 登录/管理员处理 |
| RESOURCE_NOT_FOUND | 404 | 不重试 | 核对任务与用户 |
| IDEMPOTENCY_CONFLICT | 409 | 不重试 | 新意图生成新 key |
| INVALID_OPTIONS / INVALID_POLICY | 422/503 | 不静默默认 | 修正输入/管理员配置 |
| UPLOAD_TOO_LARGE / UNSUPPORTED_FILE | 413/415 | 删除本次临时文件 | 拆文件/换合法格式 |
| QUEUE_FULL / USER_JOB_LIMIT | 429，Retry-After:10 | 客户端最多指数退避，不重复意图 | 等待或取消自己的任务 |
| MODEL_UNAVAILABLE | 503 或 failed | 无模型/鉴权错误不自动重试 | 检查本地模型和绑定端口 |
| EXTRACTION_FAILED / OCR_UNAVAILABLE | failed | 保留原文件，不调用 LLM | 修复OCR或使用文本文件 |
| SOURCE_MAPPING_INVALID / COVERAGE_INCOMPLETE | failed | 禁止回退截断路径 | 修复解析/计划并显式重试 |
| TOKENIZER_UNAVAILABLE / TOKEN_BUDGET_EXCEEDED | failed | 超限仅一次重规划 | 核对 tokenizer/模板/预算 |
| LLM_TIMEOUT / LLM_NETWORK_ERROR | failed或有界重试 | 遵守03重试及slot确认 | 检查服务；不直接加大所有超时 |
| INVALID_MODEL_JSON | failed或有界重试 | 一次修复，计入预算 | 保留诊断摘要 |
| CITATION_INVALID | quality_warning | 风险 rejected；不编造引用 | 补充法规证据或人工复核 |
| TASK_TIMEOUT | failed | 不自动整单重跑 | 检查实际开销，显式重试 |
| INSUFFICIENT_STORAGE | 507或failed | 停止接单 | 释放经授权空间；保留已有数据 |
| DATABASE_BUSY / PERSISTENCE_FAILED | 503或failed | 短事务重试，最多3次/总2秒 | 检查锁/磁盘；不得假报done |
| EXECUTOR_INTERRUPTED | interrupted | 不自动重跑 | 确认slot空闲后新建retry |

新 API HTTP 错误 envelope 为 `{"error":{"code":"...","message":"...","retryable":false,"request_id":"..."}}`。旧 API 保持 `detail` 字符串，并可增加顶层 error_code。前端 `ensureOk` 必须兼容两者。已经进入队列的运行错误通过 JobView 返回，不能再依赖上传 HTTP 是否500。
