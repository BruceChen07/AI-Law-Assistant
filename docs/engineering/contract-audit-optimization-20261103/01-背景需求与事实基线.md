# 01 背景、需求与事实基线

## 1. 项目与使用场景

系统供法务、财税人员在本地/企业内网上传 PDF、DOCX，检索本地法规，识别合同风险，查看证据定位并导出报告。输出是人工审核辅助材料，不构成自动法律裁决。

现有技术为 React/Vite、FastAPI、SQLite、ONNX Embedding、可选 Reranker/OCR 和本地 llama.cpp。保留法规管理、记忆模式、税审独立流水线、用户管理及现有报告格式。本次优先改造合同审计经典路径，因为当前配置禁用了记忆模式。

场景顺序：

1. 业务用户登录，上传文本 PDF、扫描 PDF 或 DOCX。
2. 文件保存后立即取得任务 ID，看到排队/解析/检索/逐块审计状态。
3. 长文全文送审，用户能刷新页面恢复任务、取消任务、查看失败原因。
4. 完成后查看风险及原文位置，导出与当前系统兼容的报告。
5. 运维人员检查真实耗时、模型配置、失败率及容量；工程师可复现每个请求。

## 3. 用户工作区保护

设计时未提交修改涉及 README、合同路由/提示词、配置、启动停止脚本、前端 App/API/翻译、lockfile、记忆反馈。另有未跟踪模型、运行目录、架构文档。实现者必须重新运行 `git status` 和针对性 `git diff`，登记变更归属，禁止 reset/clean/覆盖未确认内容。

历史测试记录仅供排查：曾出现 Windows 原生访问冲突、C 盘满、管理员初始化 hash 异常、前端 lint 和依赖安全告警。不得认为它们目前一定仍存在，也不得认为已修复；P0 重新分类复现。

## 4. 功能需求与优先级

| ID | 优先级 | 需求 | 可验证完成条件 |
|---|---|---|---|
| R01 | P0 | 源文本可追溯、无静默漏段 | 每个非空白源字符都有映射；送审计划覆盖率 100% |
| R02 | P0 | 按完整消息预算均衡分块 | 每次输入+输出预留+安全量不超真实上下文；长条款可拆分 |
| R03 | P0 | 风险正确性 | 严格 JSON；所有引用合法；风险可定位；缺失风险经全文检索验证 |
| R04 | P0 | 异步任务与持久化状态 | 短提交响应、独立轮询、断连继续、刷新恢复、任务隔离 |
| R05 | P0 | 有界执行和失败可见 | 并发 1；排队有上限；请求和任务超时；可取消；失败不伪装完成 |
| R06 | P1 | 减少重复计算 | 前缀缓存实测；提示词去重；安全的解析缓存 |
| R07 | P1 | 兼容现有使用 | 保留旧 API、定位/导出格式、中英模式和受控回退 |
| R08 | P0 | 可观测与复现 | 每个任务/块/尝试可串联，保存配置和版本摘要 |
| R09 | P1 | 当前硬件调优 | 4/6/8/10 线程及 batch 对比，保留质量门槛 |
| R10 | P2 可选 | 真正小模型分工 | 独立开关、独立评测；未批准前关闭 |

P0/P1 是需求重要性，阶段 P0～P6 是实施顺序，二者不可混用。

## 5. 指标定义

| 指标 | 门槛/目标 | 口径 |
|---|---|---|
| 计划覆盖 | 必须 100% | 非空白源字符被唯一主审计区间覆盖的比例；辅助上下文不计入 |
| 有效审计覆盖 | `done` 必须 100% | 有合法成功响应的主审计区间并集/全部应审区间；不代表模型理解率 100% |
| 来源映射 | 必须 100% | 规范化后每段可映射原文页/字符区间；未知页标记 null，不造页码 |
| 单请求预算 | 必须全部满足 | 以实际模板 token 计数；不能只按条款字数 |
| 新 API 提交 | P95 ≤ 2 秒 | 文件接收完毕到任务入库返回；50 MiB 以内，排除网络上传时间 |
| 查询响应 | P95 ≤ 500 ms，P99 ≤ 1 秒 | 满负载生成时，单机 5 个查询客户端，见 07 |
| 状态可见 | 状态变更后 ≤ 3 秒；心跳 ≤ 10 秒 | 2 秒轮询；HTTP 心跳不代表 token 正在增长 |
| 同硬件提速 | 发布目标 ≥ 30% | 相对 P1 全覆盖修正版基线的配对暖运行中位数；质量门必须先通过 |
| 28 页样本 | 优化目标 ≤ 25 分钟；探索目标 ≤ 15 分钟 | 非承诺；若模型输出更多风险则报告质量/耗时权衡 |
| 质量 | 高风险标注召回 100%；全部风险召回 ≥ 95%；精确率 ≥ 90% | 至少 20 份经专家标注脱敏样本；定义见 07 |
| 资源 | 无 OOM，进程稳定，无无限队列/日志 | 工作机总内存峰值 < 90%；队列最多 3 个待运行任务 |

若 P1 修正漏段后耗时上升，不得恢复漏段实现以“达标”。P5 未达性能目标，必须提交差距、证据和业务批准的例外，不能标记性能验收通过。

## 6. 非功能与明确不做

- 原生非管理员安装；无 Docker、Redis、Celery 或强制外部云服务。
- 模型、依赖由离线包或企业白名单提供；禁止在任务中自动联网拉模型。
- 生产一台机器一个应用进程、一个任务执行器、一个 llama.cpp slot；不承诺多机高可用。
- 上传 ≤ 50 MiB；输入合同中的指令只作为数据，不可修改系统角色或执行命令。
- 仅输出风险辅助建议，保留人工审批；不能牺牲白名单和跨条款约束换速度。
- 不自动改 BIOS、不默认启用核显加速、不卸载 Ollama、不清理用户模型或系统缓存。
- 本期不做自动恢复到半个生成请求、不做跨用户结果共享、不重构税审数据模型。

## 7. 待业务确认与默认处置

| 项目 | 未确认时默认值 | 对实施的影响 |
|---|---|---|
| 脱敏合同和人工标注 | 只用合成合同 | 可完成开发，不得签署法律质量及真实性能验收 |
| 生产维护窗口 | 不重启生产、不迁移真实库 | 用隔离配置和临时库开发 |
| Trace 保留期 | 原始 prompt/response 默认不持久化；诊断时显式启用 7 天 | 元数据保留 90 天；业务报告不自动删除 |
| 模型/驱动替换 | 保留当前 GGUF 和 CPU 运行时 | 可做离线对比，不能默认切换 |
