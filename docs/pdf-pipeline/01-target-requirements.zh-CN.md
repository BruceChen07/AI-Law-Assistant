# 目标 PDF 处理需求拆解

更新时间：2026-10-15
来源：`reports/weknora_pdf_analysis_2026-10-15.md`

## 1. 核心需求

基于目标文档梳理，新的 PDF 模块需要覆盖以下能力：

1. 文本型 PDF 快速抽取
2. 扫描型 PDF OCR 回退
3. 混合型 PDF 的页面级路由
4. PDF 页面预览与文本块定位
5. 数字化 DOCX 导出，供审计与留档复用
6. 统一元数据输出，供审计、预览、导出、前端展示共享

## 2. 性能指标

结合目标文档与当前项目场景，落地指标如下：

1. 文本型 PDF 优先走非 OCR 路径，降低耗时
2. 扫描型 PDF 才触发 OCR / 数字化，避免全量重处理
3. 页面预览需要限制分辨率与长边尺寸，避免大图撑爆内存
4. 预览默认页数受控，避免一次性生成全部缓存

## 3. 兼容性要求

1. 支持 `.pdf`、`.docx`
2. 支持文本 PDF、扫描 PDF、混合 PDF
3. 兼容现有合同审计上传/预览/导出接口
4. 兼容内网部署，不依赖云端回退

## 4. 安全与稳定性要求

1. 保留文件类型校验
2. 保留大小限制
3. 保留 OCR 失败时的清晰报错
4. 保留数字化缓存复用能力
5. 所有元数据统一输出，便于问题排查

## 5. 与当前项目的取舍结论

不直接照搬目标项目，而是采用“双路径融合”：

1. 借鉴目标文档中的页面级 PDF 路由思路
2. 保留当前项目 MinerU 数字化到 DOCX 的强项
3. 新增统一 `pdf_pipeline` 服务层，承接抽取、预览、数字化策略编排
